# 无法从 diff 或计划确认的需求

属于 superpowers:subagent-driven-development 的一部分。

整分支自审中，你会发现一些需求落在横跨多个任务的交互上，仅凭 diff 无法完全核实：存在于未改动代码中的行为、跨任务才成立的约束、计划里写了但 diff 上看不出是否被满足的要求。

这些不阻塞其余自审，但你必须亲自逐条解决——计划与跨任务上下文在你手里。

**判断标准：无法从 diff 或计划确认一项需求确实被满足时，把它当作真实缺口对待**，和其他发现一起进入修复波。不要因为它"大概实现了"就放行：这类缺口正是收尾自审唯一能抓住的东西，放过去就等于没审。

如果你能确认它确实被满足（在别处已有实现、或由既有测试覆盖），把确认的依据记入账本一行再继续——下一次压缩之后你不会再记得这次推理。
